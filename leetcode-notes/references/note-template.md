# 模范笔记的组织方式

参考用户的 `leetcode/04 网格图/01 网格图 DFS.md`。可以访问时先读现有相关段落；参考文件不在当前库时，下面的写法已自包含，不依赖固定机器路径。

## 文件与排版

- 一篇笔记围绕一个可复用的小专题，如 DFS 连通块、定长滑窗、二分求最小；同一篇可收纳多道代表题。
- YAML 沿用 `title`、`aliases`、`tags` 等现有属性，只有已知值才填写。文件名或 YAML 已提供标题时，不强制再写重复 H1。
- 顶部一行双链返回题单、跳转关联专题；随后使用 `[!summary]` 提示框写一句核心主线。正文以 `##` 编号分节、`###` 区分题目，尽量不深嵌标题。
- 短段落和列表解释，粗体标关键判断，反引号标变量/表达式；表格只用于真正需要并列比较的内容。`[!tip]` 用于关键结论，避免到处加提示框。

## 推荐阅读顺序

1. **先记住主线**：用一句具体的话说清算法职责或判断依据，例如外层循环发现区域、DFS 搜完整个区域。
2. **核心思路：边看图边理解**：简短解释输入和规则，随即展示 Datacore；再按“看图理解几个关键概念”回答当前例子里的问题。接一段静态流程或推演，解释算法为什么成立。不要先铺长篇理论再让用户看图。
3. **核心模板**：给完整、可复用且前提明确的代码。关键行就近注释原因；解释变量、状态、返回值与上层调用的关系。优先沿用同一个小例子连接图形、文字和代码。
4. **具体题目**：每题用“题目要什么？”短句切入，列关键条件，给完整代码，随后说明“和通用模板/上一题相比，改了哪里”。题目特有的新机制、边界或个人疑问在这里补充。
5. **我问过的疑问**：集中回答专题共性问题。用真实问题作标题，直接解释；必要时配一个最小例子或代码片段。不虚构个人提问，不强制列状态表。
6. **易错点清单**：使用未勾选的复习自检项，写清具体条件与正确做法，避免“注意边界”这种空话。与个人已发生的错误区分。
7. **相关题目与笔记**：短句说明每道题或关联专题的迁移点，双链跳转实际已有笔记，避免只有一串题号。
8. **复杂度与参考**：公共复杂度集中说明，计入关键空间成本；题目成本不同则在题内单列。文末列实际阅读的灵神题单、题解及必要语言文档，具体题的解法依据就近标注。

以上是顺序参考，按主题需要合并或略去无材料的部分，编号随之调整。不为了凑结构填空栏目。补一道题时只更新对应部分，不重写全篇。

## 单题保持紧凑

一般使用这几个内容块，不强制每块另设标题：

- **题号与题名**：附原题链接，并用一行记录已确认的解法依据。
- **题目要什么？**：一两句话说明输出，补充影响写法的条件。
- **完整代码**：沿用所选方法；公共操作已在模板解释过时不再逐行重讲。
- **相对模板的变化**：指出输入类型、判定、返回值或答案统计方式的变化；仅有新原理时再展开推导与推演。
- **本题的个人卡点**：有真实记录就解释在该题里；共性问题链接答疑节，没有个人记录则不强塞空表。

相邻题形成对照时，可用一个表格总结差异。如 200 与 695 对比字符串/整数、计数/求面积、DFS 是否返回大小。表格表达差异，不代替必要理由。

## 写作边界

样板提供结构与表达方式，不证明其代码来自灵神，也不代表所有主题都该沿用 DFS 的状态和变量。来源、用户解法选择及个人经历真实性按主文件执行。保留用户的风格，同时补上实际使用的来源和必要的正确性解释。
