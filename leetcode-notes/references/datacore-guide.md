# Datacore 交互与配色

## 根据教学目标选择交互

小专题核心讲解配一个真正帮助理解的 Datacore 交互；先简述场景和规则，再让用户操作，随后对照图解释。章节入口需要展示整体核心时也采用这个顺序，综合章节展示方法关系或明确限定范围的基础机制，不强凑通用算法。

| 要理解的内容 | 适合的交互 |
| --- | --- |
| 同一数据的不同含义 | 视角切换，如原始地图 / 连通块染色 / 访问顺序 |
| 变量怎样随算法改变 | 逐步演示，如边界收缩、窗口移动、入栈出栈 |
| 两种条件或方法的差别 | 方案切换或并列对比，保持共同输入与布局 |
| 参数改变的影响 | 有界输入或预设案例，显示对应结果与理由 |

**不强制所有组件都有前进、后退、重置。** 只有逐步演示需要这组控件，并正确处理首尾和重置；视角切换用清晰的按钮即可。控件服从理解目标，非进度统计或算法名称目录。

组件的结果、分组和访问次序应由相应算法或明确验证的过程产生，不为展示编造。输入、下标、状态、输出用清晰文字说明；必要时交代搜索方向等约定。相同数据切换视角尽量保持布局，让用户比较含义而非重新找位置。静态正文也须解释相同机制。

## 固定的个人配色

参考 `leetcode/04 网格图/01 网格图 DFS.md`，默认使用柔和填色配深色字：

| 元素 | 背景 | 文字 |
| --- | --- | --- |
| 浅绿分组/状态 | `#D9F0E2` | `#25364D` |
| 浅蓝分组/状态 | `#DCE8FC` | `#25364D` |
| 浅橙分组/状态 | `#F9E3C5` | `#25364D` |
| 中性元素 | `#F0F4F7` | `#315B49` |

固定填色同时指定文字色，避免深色主题继承白字。颜色语义由算法决定，同一图内稳定，同时用字母、数字或标签区分；类别多于三种时用编号或聚焦选择辅助识别，不只循环三色。

外框使用主题的 `--background-primary`、`--background-modifier-border`，说明用 `--text-muted`，普通文字用 `--text-normal`。未选按钮用 `--background-secondary`；选中按钮用 `--interactive-accent` 和 `--text-on-accent`。禁用态实际设置 `disabled`。

外框圆角约 `14px`，按钮/数据格约 `9px`，标签约 `6px`；细边框、`5–10px` 间距、约 `10px` 内边距。沿用正文的字体和字号，用粗体突出关键数字，不加厚重阴影、渐变或装饰性卡片。控件可键盘操作，窄屏可换行或横向滚动，样式局限组件。

## 实现与验证

- 使用自包含的 `datacorejsx`，返回函数组件，Hook 用 `dc.useState`、`dc.useMemo` 等并置于组件顶层；不假设全局 `React`。不依赖其他笔记脚本、网络、外部库或持久化写入。
- 视角切换可复用同一次算法的计算结果；逐步演示可用纯函数生成帧，保存独立状态快照，防止后续修改污染历史。数据/方案切换后处理索引越界，不默认自动播放，定时器须清理。
- 生成时读取目标库 Datacore 的启用状态、版本和 `enableJs` 配置，不自动安装或改配置。缺环境仍可准备正文与组件，在回复说明限制。
- 核对结果、状态和正文代码的一致性，适合时与独立参考实现对照；有工具时检查 JSX/Preact 渲染及实际提供的按钮、输入和边界。仅解析通过不等于界面通过，未打开 Obsidian 就不能声称已确认实际效果。
- 自拟输入标为“自拟示例”；主题、对比度、窄屏和操作检查按实际情况报告。插件版本、测试环境及验证状态放在回复，不混入学习正文。
