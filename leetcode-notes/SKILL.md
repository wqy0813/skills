# 中文力扣专题笔记

目标是写出能理解、能改题、能复习的学习笔记。写作结构、排版和交互配色已完整定义在本 Skill 及其参考文档中，不依赖作者的私人笔记。默认中文 Obsidian `.md`，代码语言沿用用户材料，未指定时用 Python。

## 1. 定位专题与资料

读取 [题单与目录映射](references/topic-sources.md)，找到当前章、原题单小节和现有笔记；写作前读取 [笔记结构](references/note-template.md)，生成交互时再读 [Datacore 指南](references/datacore-guide.md)。

默认按“章节目录 → 小专题笔记 → 代表题”组织，例如网格图目录下分别写 DFS、BFS。章节入口保留总体核心、方法关系和题单；小专题开头解释自己的核心及与章节共性的关系。已在入口讲清的内容简述并链接，不重复长篇。沿用现有目录、编号、标题和导航；只有用户要求时才迁移旧文件或重排题单。

用户没有现成笔记库或相同目录时，按指定保存位置建立本次所需文件；保存位置不明确才询问。用户另行提供的参考笔记仅作可选定制材料，不要求其具备某个固定文件名或目录。

成文前查阅本次相关的灵神原文：题单开头/基础教程 → 小节说明与答疑 → 必要时本节第一道或前几道代表题的作者题解。说明本节复用了什么、新增了什么、为什么要改；没有额外机制时不强凑差异。不能仅凭标题、搜索摘要或代码推测作者讲解。

## 2. 区分公共讲解与具体题解

**公共核心、交互和通用模板默认统一采用灵茶山艾府原文的一种明确写法。** 例子、变量名、状态定义、操作顺序和答案更新时机保持对应；选择原文中的某一版本时就近注明。用户选择保留个人题解，不代表公共交互也要增加个人写法的对照模式；用户明确要求其他公共讲解方式时再调整。

**具体题目单独确认解法。** 没有明确选择时询问：“这道题按灵茶山艾府的优化解法，还是按你自己的解法整理？有哪些写错过或还不理解的地方？” 已明确本题、本节或本批选择时直接沿用，不重复询问。等待答复可继续已有依据的公共核心、模板与来源工作。

- **灵神优化解法**：读取该题作者原题解的对应版本，说明优化了什么及其前提；在题内附原题解链接。不默认最后一种写法就是最优。
- **用户自己的解法**：以用户代码/思路为主。缺材料则请其补充；错误给出解释与反例，区分原稿和修正，不悄悄替换为灵神版本。

代码附近明确角色：灵神公共模板、我的原代码、修正代码等；助手独立补写的代码或来源不明的存档不能标为“我的原代码”或灵神原解。融合改写注明借鉴点。来源无法访问时说明缺少什么，可继续有依据的部分，但不能把独立推导标成灵神原文。

## 3. 组织讲解

采用“先记住一句主线 → 同一个小例子的交互与解释 → 通用模板 → 具体题目及变化 → 个人答疑 → 易错清单 → 关联笔记与复杂度”的阅读顺序，详见结构参考。允许按内容合并小节，不把每题写成重复的大表单。

核心放在笔记前部，用最少场景说明让用户先看图，再结合图理解概念与状态。通用模板单独讲清关键操作、变量意义和正确性，注释解释为什么。具体题目给完整代码，重点解释相对模板或前题改变了什么；已有公共解释通过链接或一句话复用。

**代码避免重复展示**：仅改变量名、排版、初始化位置，或改成等价表达时，默认保留用户选定的一份，差异用短句解释；不要自动生成“整理版 + 原稿”两份完整代码。公共模板与单题写法实质相同时通过链接复用。纠错或明确比较不同方法确需两版时，说明各自用途；细则和 Obsidian 折叠语法见[笔记结构](references/note-template.md)。

**个人问题按作用范围放置**：题目特有的易错点与疑问放在该题内，专题共性疑问集中放“我问过的疑问”，并从相关题链接过去。优先用短问答、代码或小反例解释，不强制填写依据/状态表，也不制造空白栏目。

只从本次对话、用户提供或指定的可访问相关材料提取个人经历；推测需标明待确认，信息不足时询问。无记录不虚构“我曾经写错”，一般提醒放“易错点清单”。勾选框用于复习自检，不自动勾选或推断已掌握。

## 4. 验证与保存

- 保留正确函数签名、导入和完整可用代码。公共推演与复杂度可集中讲，只有某题机制或成本不同时另补；不强制每题重复。计入递归栈、排序、切片及实际容器成本。
- 可运行时检查最终代码的示例和有针对性的合法边界，必要时小规模对拍；公共测试结论也注明适用范围。只报告实际运行/推演情况，本地通过不能写成平台 AC。交互验证按 Datacore 指南执行。
- 更新已有笔记时保留批注、原代码、有效双链、YAML 和组件，按题号与小专题查重。修复本次改动影响的链接，不自动改进度、日期或熟练度。只改 Skill 的任务不顺带改笔记。
- 用户仅问代码片段时直接处理局部；说“先提示/带我做”时按需引导，不提前展开完整答案。用户另要错题本时更新条目并链接对应题解，不把题目特有疑问全部移出题内。

交付前检查：主线清楚，例子贯穿图与模板，单题变化明确，个人问题真实，来源可追溯；代码角色清楚、避免无意义的重复代码，图与模板一致，折叠块之后的正文仍能正常解析。简短报告文件位置和实际验证；工具版本、测试环境等制作信息不混入学习正文。
